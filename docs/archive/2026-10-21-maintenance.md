# Обслуживание oggy: решения 2026-10-21

Исторический контекст обсуждения и PR #2, не постоянная политика.
Решения впоследствии могут меняться; актуальное поведение задают конфиги
и эксплуатационная документация. Номера сохранены из исходного аудита.

- 2-3: исходники и инструкции хранить в Git, работу агентов вести через ветки,
  push и PR для ревью: изменения должны оставаться видимыми и проверяемыми.
- 4-9: удалить согласованный legacy и неиспользуемые остатки вместо их поддержки.
- 10-11: проверенные dumps БД перед ежедневными Btrfs snapshots; хранить
  7 дней, 4 недели, 3 месяца. Еженедельный Nix GC. Короткий срок выбран пользователем.
- 13: оставить activation scripts: выгоды от перехода на tmpfiles сейчас не видно.
- 14: объяснить числовые UID/GID образами в комментариях, без новых host users.
- 15: удаленное хранение backups нужно позже; пока только TODO, без выбранного target.
- 16: сгруппировать конфиги по хостам, сервисы oggy собрать в selfhost;
  Qingping назвать smarthome, Grafana assets явно поместить в grafana.
  Причина: нынешние selfhost/remote и отпочковавшиеся сервисы затрудняют навигацию.
- 17: явно задать существующий Prometheus datasource UID, используемый dashboards/alerts.
- 18: сохранить Unix socket Grafana: пользователю нравится этот способ подключения.
- 19: проверить механизм создания Docker-сети и показать отдельным PR.
- 20: подготовить переход на nftables отдельным PR для ревью удобства и политик.
- 21: общие параметры задавать корневым модулем oggy и получать через аргументы
  модулей по умолчанию: привычнее, чем дополнительный values-файл и ручные imports.
- 22: показать sops-nix отдельным PR; миграция секретов еще не выполнена.
- 23: оставить один официальный T3 nightly с собственным updater, убрать Nix runtime.
  Codex CLI установлен через npm, вход и история сохраняются; T3 обновляет CLI.
- 24: сохранить pin mqtt2prometheus; остальные custom pins убирать по возможности.
- 25: сохранить selfhost-remote как заготовку, описать назначение и ограничения.
- 26: использовать один nixfmt-tree через nix fmt.

Сеть, nftables и sops-nix не выкладывать из этого обсуждения без отдельного ревью.
HTML страницы и развернутый proposal не сохранять в PR #2: нужен краткий контекст,
а не дублирующая текущие конфиги спецификация.
